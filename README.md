# Готовность

Личный сайт: риски и стремления (две колонки, шкалы прогресса, профиль в боковой панели), действия с весами, промпт для нейросети.

## Запуск

```bash
go run .                      # http://127.0.0.1:8080
go run . -dir mydata          # другая папка с учётками
go run . -data old.json       # старый файл данных, который получит первая учётка
go run . -addr 127.0.0.1:9000 # другой порт
```

Нужен Go 1.22+. Внешних зависимостей нет. htmx подгружается с CDN в браузере.

## Учётки

Вход по логину и паролю, у каждой учётки свои кейсы и профиль. Учётки нужны, чтобы разделить людей
за одним компьютером: сервер слушает только localhost, HTTPS и защиты от перебора паролей нет,
поэтому открывать его в сеть нельзя.

- При первом запуске учёток нет: страница входа предложит создать первую. Она получит данные из старого `data.json`
  (сам `data.json` не меняется и дальше не используется).
- Пароли хранятся как PBKDF2-HMAC-SHA256 с солью. Сессия — подписанная cookie на 30 дней, переживает перезапуск сервера.
- Забытый пароль восстановить нельзя: останови сервер, удали учётку из `data/users.json` и создай заново с тем же логином —
  данные в `data/accounts/<логин>.json` подхватятся.

## Данные

Всё лежит в папке `data/` (в git не попадает):

- `users.json` — логины и хеши паролей
- `session.key` — ключ подписи сессий; если удалить, все выйдут из учёток
- `accounts/<логин>.json` — данные учётки

Править можно и в интерфейсе, и руками в файле учётки, но файл сервер читает при первом входе в учётку:
если правишь вручную, останови сервер, поправь файл и запусти снова, иначе следующее сохранение из интерфейса перезапишет твои правки.

- `profile` — возраст, пол, страна, город, профессия, семейное положение, дети, здоровье (`health`) и «о себе» (`about`);
  попадает в каждый промпт. Пол, семейное положение и дети выбираются из списка
  (`male`/`female`, `single`/`in_relationship`/`married`/`divorced`/`widowed`, `no`/`yes`), пусто — не указано.
- `description` у кейса — подробное описание для нейросети, может быть пустым.
- `kind` — `risk` (риск) или `aspiration` (стремление); при создании кейса тип выбирается первым.
- `base_probability` — только у риска: вероятность, что случится, доля от 0 до 1 (`0.3` = 30%).
  У стремления базы нет: оно начинается с 0% выполнения, цель — 100%.
- У действия одно число для расчёта — `weight`, «вес действия, %»:
  - у риска это процентные пункты: база 30% и вес `-10` дают 20%; текущая вероятность = база + веса выполненных действий (от 0 до 100%);
  - у стремления это доля цели от 0 до 100: выполнено = сумма весов выполненных действий. Веса всех действий
    в сумме должны дать 100, иначе на странице кейса предупреждение. Шаги незакрытого действия в процент не идут.
  Вес нейросети хранится рядом в `llm_weight` и в расчёт не попадает, пока не нажата «Принять»
  (у действия) или «Принять все веса нейросети» (у кейса).
- `requires` / `excludes` — id действий; в интерфейсе выбираются из списка названий, в том числе из других кейсов.
- `steps` у действия — чеклист шагов. На вероятность шаги не влияют: когда отмечен последний шаг, действие
  отмечается выполненным само, а если снять шаг у выполненного действия, отметка с действия снимается.
  Для стремлений промпт просит нейросеть предложить шаги, их можно добавить галочками в превью.
- Действия в кейсе отсортированы по весу: у риска сверху те, что сильнее снижают вероятность, у стремления — самые весомые.
- Старые форматы файла читаются и переносятся сами: множители (`multiplier`, `my_multiplier`, `llm_multiplier`) у рисков
  становятся весами с тем же эффектом при базовой вероятности (база 10% и ×0.9 → вес −1), у стремлений отбрасываются —
  там веса задаются заново.

## Файлы

- `model.go` — структуры, расчёт, проверка данных и связей
- `store.go` — загрузка и атомарное сохранение
- `accounts.go` — учётки: регистрация, пароли, сессии, данные каждой учётки
- `login.go` — вход, регистрация, выход, проверка сессии на каждом запросе
- `prompt.go` + `prompt.tmpl` — сборка промпта, разбор и применение ответа (веса: `weight`); у риска и стремления разные инструкции
- `risks.go` + `risks.tmpl` — «Сформировать риски» на главной: промпт по профилю и уточнению, превью, добавление новых кейсов
- `percent.go` — что значит вес у риска и у стремления, допустимые значения, подписи
- `server.go` — маршруты и обработчики
- `edit.go` — редактирование и удаление кейсов, действий, шагов, профиля
- `templates/` — страницы
- `static/` — стили и логотип; встраиваются в бинарник и отдаются по `/static/...`
