# Spec Delta

## Purpose

Позволяет разворачивать грубый шаг действия в более мелкие под-шаги по ответу нейросети, ссылаясь на шаги по их номеру.

## ADDED Requirements

### Requirement: Steps are numbered and referencable

Каждый шаг в чеклисте действия ДОЛЖЕН отображать свой порядковый номер (начиная с 1, в порядке следования),
и по этому номеру на шаг ДОЛЖНО быть возможно сослаться в потоке уточнения.

#### Scenario: Numbers follow checklist order
- **WHEN** открыта страница кейса с действием, у которого несколько шагов
- **THEN** каждый шаг показывает свой номер, начиная с 1 в порядке следования в чеклисте

#### Scenario: Number reflects a single step
- **WHEN** в чеклисте есть шаги и пользователь смотрит на конкретный шаг
- **THEN** этот шаг имеет ровно один номер, по которому его можно однозначно выбрать для уточнения

### Requirement: User can select a step to refine

В каждом действии ДОЛЖНА быть возможность открыть поток «Уточнить шаг» и выбрать один из шагов этого
действия по его номеру.

#### Scenario: Selector lists the action's steps
- **WHEN** пользователь открывает «Уточнить шаг» у действия с несколькими шагами
- **THEN** селектор показывает шаги этого действия с их номерами

#### Scenario: No steps available
- **WHEN** у действия нет шагов
- **THEN** поток «Уточнить шаг» для этого действия недоступен

### Requirement: Refinement prompt uses a dedicated schema and carries context

Формирование промпта уточнения ДОЛЖНО использовать схему, отдельную от оценки весов действий,
и ДОЛЖНО включать краткий контекст по кейсу и действию, короткий список шагов кейса и выбранный шаг.

#### Scenario: Prompt contains context and step list
- **WHEN** пользователь формирует промпт уточнения для выбранного шага
- **THEN** промпт содержит краткий контекст и короткий список шагов, а его схема отличается от схемы оценки весов

### Requirement: Weight-estimation and refinement replies are mutually exclusive

Ответ, корректный для оценки весов действий, НЕ ДОЛЖЕН приниматься потоком «Уточнить шаг», и наоборот:
корректный ответ уточнения НЕ ДОЛЖЕН приниматься потоком оценки весов.

#### Scenario: Estimate reply rejected by refinement
- **WHEN** пользователь вставляет корректный ответ оценки весов (с полями `case_id`/`actions`) в поле «Уточнить шаг»
- **THEN** показывается ошибка схемы, и ни один шаг не изменяется

#### Scenario: Refinement reply rejected by estimation
- **WHEN** пользователь вставляет корректный ответ уточнения (с полями `action_id`/`step_id`/`steps`) в поле «Ответ нейросети» оценки весов
- **THEN** показывается ошибка схемы, и никакие веса не изменяются

### Requirement: User chooses which sub-steps to apply

Корректный ответ уточнения ДОЛЖЕН показать список под-шагов, и пользователь ДОЛЖЕН иметь возможность
отметить, какие из них применить. Применение ДОЛЖНО удалить выбранный шаг и вставить на его место
только отмеченные под-шаги, каждый — как отдельный невыполненный шаг.

#### Scenario: User selects a subset
- **WHEN** применяется корректный ответ, и пользователь отмечает только часть под-шагов
- **THEN** исходный шаг удаляется, и на его место добавляются только отмеченные под-шаги

#### Scenario: User selects none
- **WHEN** применяется корректный ответ, и пользователь не отмечает ни одного под-шага
- **THEN** показывается ошибка, и ни один шаг не изменяется

#### Scenario: Other steps stay untouched
- **WHEN** применяется корректный ответ для одного шага
- **THEN** остальные шаги и действия кейса остаются без изменений

### Requirement: Invalid answer changes nothing

Если вставленный ответ не соответствует схеме уточнения или содержит пустые названия под-шагов,
система ДОЛЖНА показать ошибку и оставить все шаги без изменений.

#### Scenario: Malformed reply
- **WHEN** пользователь вставляет текст, не соответствующий схеме уточнения
- **THEN** показывается ошибка, и ни один шаг не изменяется

#### Scenario: Empty sub-step title
- **WHEN** корректный по структуре ответ содержит под-шаг с пустым названием
- **THEN** показывается ошибка, и ни один шаг не изменяется
